# V19.4 測試版快速部署計畫

本輪允許本機檢查、提交／推送指定分支、更新 Draft PR #25 與 Render 唯讀盤點。資料歸零、Migration、部署、合併與 Email 寄送均未授權。快速部署不會重新啟用啟動重設。

## 本機證據

- 135/135 unittest PASS：既有 55、初始化 20、總館簽核 15、PostgreSQL 工具離線安全 45。
- 隔離空白 SQLite 明確初始化後，FastAPI startup、首頁與 /health PASS，外部 socket 禁用。
- 已具備 Schema 的正常啟動只驗證，不建表或同步／清空資料。
- 總館首次簽核、相同／不同重送、日報鎖定、原始簽核人時間與並行保護皆有回歸。前端區分 already_signed 與 HTTP 409。
- PostgreSQL 第一階段及後續唯讀盤點的結果沿用既有證據；本輪沒有執行資料庫 Migration、第二階段寫入或資料清理。

## 部署前必要核對

Render 實際資料庫選擇由服務 DATABASE_URL 決定；無此設定會使用 DATA_DIR/app.db。Repository 的 render.yaml 不是線上設定的證據。必須確認服務工作區、分支、自動部署與實際環境；不得將獨立驗收庫視為目前網站資料庫。

新版空庫不能直接服務：先經審閱執行基礎 Schema（含 branches）及既有 Migration、V19.4 branch_signers／版本紀錄，再獨立建立測試基本資料。現有 schema_init PostgreSQL 入口只允許專用驗收庫，不是任意網站資料庫的部署命令。

基本登入資料：users 管理者與總館帳號及密碼雜湊；drivers 的司機與 PIN／裝置設定；routes、branches 及路線分館關聯；分館 QR access_token_hash 與 PIN；app_settings 的人工路線司機設定。空 Schema 不會建立這些資料，也不能靠環境變數自動建立。不得直接呼叫正式名冊同步或示範種子以初始化線上 PostgreSQL。

## 歸零方案（尚未授權執行）

1. 先確認目標為使用者指定的測試網站資料庫，唯讀列出表、外鍵、資料筆數及日期範圍。
2. 建立可還原的資料庫備份及部署設定快照，備份置於受控位置；不納入 Git，也不輸出憑證。驗證備份可讀且有復原步驟後，才提交精確刪除範圍供授權。
3. 預計保留 users、drivers、routes、branches、branch_signers、app_settings、schema_migrations，以及 QR/PIN、帳號密碼雜湊、司機啟用／裝置設定。休館與停送排程另行確認，不默認刪除。
4. 可提案歸零配送、每日路線、品項、更正、交接／分派、路線簽名與日報；簽名與時間會隨業務資料刪除，必須在授權中特別列明。稽核、Email 紀錄、session 與密碼重設紀錄分開決定，不默認一併刪除。
5. 審閱實際外鍵後依子表至父表順序，在明確交易中依已核准的資料範圍刪除。遇未知資料停止；不使用 DROP、TRUNCATE 或重新建庫。原合成資料限定復原器不適用於未知來源的整站測試資料。
6. 比較保留資料的完整快照及結構、Migration、刪除筆數；關閉可寫連線，以獨立 READ ONLY 連線複核。失敗整筆回滾，不自行擴大刪除範圍。

## 相容性與回滾

部署前須確認線上必要欄位完整；缺欄位會令新版 startup 停止。僅 /health 通過不代表四角色登入與所有業務流程通過。需保留上一成功部署的 commit／image 識別及資料庫備份。

程式回滾與資料回滾分開評估：Render 回滾不會復原被刪資料或 Migration；舊版啟動含原先自動重設／同步風險，不能直接視為安全回滾版本。需先檢查舊版路徑及一次性標記，必要時回滾到保留安全初始化修復的版本。沒有實測備份還原與線上 Schema 相容性前，部署風險維持中高。

第二階段 PostgreSQL 十項實測、完整四角色瀏覽器驗收仍未完成。可另行審閱是否接受此測試版風險，但本計畫不構成部署或清空資料授權。
