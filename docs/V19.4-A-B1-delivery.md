以 PR #25 的 feat/v194-safe-foundation、3123fc8 為基礎，延續既有一年歷史、停送權限及四角色功能。本次只完成使用者已提供的 A、B1 規格，不代表整個 V19.4 或 PR #25 已驗收完成。

## A：名稱統一

顯示名稱為公文－總館送出、公文－分館送出、圖書－倉庫送出、圖書－分館送出。補齊司機頁面、後端操作提示、CSV、日報／月報 Excel、正式日報 Excel／PDF 及操作文件。原有 document、document_return、outbound、inbound API／DB 欄位及 report_rows 內部鍵維持原樣，只在輸出邊界轉換標題，不改數量或公式。

## B1：分館常用簽收人員

分館 PIN／QR 登入後有獨立名單，可以新增、改名、停用及查看有效／含停用人員。沒有當日配送也能登入管理名單及看歷史；此時不產生配送，today 回傳 NO_DELIVERY，不能簽署不存在的任務。

- GET /api/branch-session/signers（預設僅有效，include_inactive=true 可含停用）
- POST /api/branch-session/signers：僅接受 name。
- PATCH /api/branch-session/signers/{id}：可改 name、active。

名稱正規化空白，1～80 字；同館同名不能重複建立（含停用）；跨館可同名。所有查詢與異動由分館 session 限定 branch_id，不接受指定別館。不同角色的 token、逾期 session 與停用分館均不可操作。異動寫 audit_logs；名單不關聯回寫 deliveries 的歷史姓名或簽名。

新增 branch_signers，沒有更動或重建既有配送表。沿用原有啟動建表機制並加 PostgreSQL advisory transaction lock；供審閱的獨立 SQL 在 docs/migrations/v194_branch_signers.sql。未執行外部 migration、未部署。另修正既有 SQLite 啟動 migration 誤查 PostgreSQL information_schema 的問題；PostgreSQL 原分支維持。

本次 B1 是名單管理；不擅自實作未收到的 B2 或變更簽收人選用／簽名儲存規則。
