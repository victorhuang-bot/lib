# V19.5｜颱風停送公文手動順延

## 目標
管理者與總館秘書在設定颱風停送時，可自行選擇公文補送工作日，不受分館固定配送星期限制；未指定日期時維持 V19.4 自動尋找下次可配送日。

## 介面
- 颱風停送類型顯示「公文補送日：自動／手動指定」及日期欄位。
- 先預覽每個分館原日期、原數量、補送日期、補送後數量，再確認儲存。
- 已有公文的目標日必須明確確認數量相加，不覆蓋。

## 後端與安全
- API 接收 optional `manual_target_date` (YYYY-MM-DD)，僅適用 TYPHOON；儲存與預覽共用同一驗證。
- 日期必須晚於整段停送期間、為工作日，且不可為全館停送、分館停送或已鎖定日；若國定假日設定存在也須排除。
- 補送日即使不是原分館固定配送星期，也可建立合法的額外配送；須檢查 `ensure_prefill_delivery` 與排程重建是否保留此紀錄。
- 僅移動未開始配送的公文預填；已配送、已簽名、已鎖定、已有司機指派或圖書品項一律阻擋。
- 同一交易處理來源作廢、目標公文加總、颱風停送與 audit；不重複搬移，不改圖書數量、歷史簽名及既有帳號。
- 使用 preview token 防止預覽與儲存期間資料變更；錯誤全部 rollback。

## 驗收
1. 星期五颱風停送，手動選下星期一，非固定配送星期的分館也能正確補送。
2. 週末、停送日、已鎖定日、早於原日期均拒絕。
3. 目標已有公文須明確同意加總；不重複計數。
4. 既有簽收、司機操作、圖書資料不變；取消停送不會自動將公文搬回。
5. PostgreSQL 隔離整合測試通過後才合併及部署。
