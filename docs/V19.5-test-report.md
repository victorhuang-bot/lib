## 變更行為

管理者及總館秘書選擇「颱風停送」後，可使用自動順延或手動工作日。手動模式必須先預覽並帶回 `plan_token` 才能儲存；目標已有公文或多日合併時，還須明確指定 `conflict_policy=sum`。沒有 token、過期 token、沒有加總同意均拒絕，且不留下異動。

手動日期嚴格採 YYYY-MM-DD，晚於整段停送期間，排除週末、global_closures（包括使用既有休館設定登錄的假日）、分館 STOP 與鎖定日。檢查現有程式後，未找到獨立國定假日／補班日資料源或假日同步服務；不宣稱自動取得政府假日，亦不新增日曆功能。未設定的假日不會自動被辨識。手動補送不受分館固定配送星期限制。

在同一交易建立既有 delivery_exceptions 的 ADD、目標公文加總、來源 VOID、停送設定與 Audit Log。不修改既有圖書欄位、簽名或憑證，不需新增表或 Migration。branch_expected_on、ensure_prefill_delivery、rebuild_service_date 都沿用既有 ADD 語義，額外補送不會在重建後消失。取消原停送不會將已搬移公文移回。

## 交易與競態

- 保留原 schedule advisory transaction lock（SQLite 為 BEGIN IMMEDIATE），PostgreSQL 另鎖來源、目標配送、分館與相關 daily_routes 資料列。
- 預覽和儲存共用規劃函式；token 綁定日期、類型、分館、原因、手動目標、來源及目標完整資料列指紋。沒有增加 row_version 的內容修改也會使 token 失效。
- 來源已有品項、支援司機、任何圖書操作、簽收或路線／區段簽名時整批拒絕。目標同樣檢查。NULL 與 0 區分處理，避免將已操作的 0 箱視為空白。
- 重送舊 token 回應 409，必須重新預覽；不會重複加總。兩個並行確認只有一個成功。
- 任何例外 rollback 全部變更，包含 ADD 及 audit；預覽無 durable writes。

## 重現命令

```sh
python -B -m unittest discover -s tests
python -B tests/v195_postgres_runner.py --pg-bin /path/to/postgresql/bin
node tests/v195_schedule_browser.mjs
node tests/v194_workflow_browser.mjs
```

PostgreSQL 工具只需開發端提供 initdb／pg_ctl／postgres；不加入正式服務依賴。此輪由 pgserver 0.1.4 的 macOS 工具 wheel 提供 PostgreSQL 16.2 binaries，不安裝為正式應用依賴。Chrome 使用拋棄式 profile；介面截圖預設寫入本機暫存 `movingmatch-v195-ui`，不含真實資料。
