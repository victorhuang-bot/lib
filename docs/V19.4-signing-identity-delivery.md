# V19.4 常用簽收人員下拉選單修復

本次延續 PR #25、feat/v194-safe-foundation，修復 2e7ba58 部署前驗收的 A15 FAIL。只接入本站簽收人員選用與必要驗證；未處理隔離 PostgreSQL、未合併、未部署，PR #26 保持獨立。

## 操作流程

正常簽收、歷史待補簽、更正簽收共用同一個本站人員選擇元件：

1. 預設為「請選擇簽收人員」，不自選第一位。沒有有效人員時提示先新增，禁止送出。
2. 「新增簽收人員」將焦點移至既有本站名單新增表單。新增後儲存至 branch_signers，重新載入選單；仍須操作者明確選擇，不自動套用新增者。
3. 選擇人員、核對四項配送數量，再手寫簽名。選單使用原生 select、至少 44px 觸控高度，320px 可用。
4. 未選人員、空白簽名、載入名單失敗時，送出按鈕保持停用。更正另需原因。清除筆跡後會重新停用送出。
5. 既有名單新增、修改、停用會刷新選單；選中者被改名／停用時清空選擇，要求重新核對。停用者不出現在新簽收的選單。
6. 無當日配送仍可透過原有 PIN／QR 登入管理名單，不產生假配送。

沒有改變四項數量的計算、原有欄位或更正留白語意。正常簽收仍待司機確認；歷史待補簽仍沿用原有完成狀態及鎖定日報例外。

## 伺服器驗證與歷史保留

POST /api/branch-session/sign 與 /correct 新增必填 signer_id（正整數）。依既有分館 session 驗證有效本站，再查詢本站 active=1 人員；伺服器從資料庫取得姓名快照，不信任自填姓名。前端同送當下顯示姓名作為過期檢查：若已改名回 409，必須重新載入選擇。

- 缺少有效 signer_id：400；跨館或停用人員、過期姓名：409；停用分館：403。
- 簽收／更正的配送查詢也限定本站 branch_id，不能利用錯誤 session task 指向別館。
- 名單異動與簽收共用既有 schedule transaction lock，避免驗證後遭停用／改名卻仍寫入舊快照；簽收異常回滾並關閉連線。
- 前端檢查 canvas 實際筆跡；後端檢查有界 PNG/JPEG data URL、有效可解碼圖片及非空白內容，拒絕空白畫布、偽圖片或外部網址。這能驗證圖片有筆跡，並不能判定真實簽署者身份。
- 沿用現有簽名儲存字串，不新增 schema。姓名、簽名與簽收時間仍保存於 deliveries 原欄位；更正只寫 correction_signer_name／correction_signature／corrected_at，保留原始姓名、原始簽名、原始簽收時間。
- 改名或停用只更新 branch_signers，不回寫任何既有配送歷史。audit 增加 signer_id 便於追溯；不記錄新增簽名影像。
- 舊頁面須重新整理；僅傳自由文字姓名、沒有 signer_id 的新簽收會被拒絕，不能繞過有效名單驗證。已成功簽收的重送維持原有冪等、不覆寫。
