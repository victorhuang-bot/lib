## 颱風停送與公文順延

管理者／總館在原「休館 / 停送 / 非固定運送」中可選颱風停送。沿用 POST /api/schedule-exceptions/range；新增 TYPHOON 別名，儲存為既有 CLOSED_ALL，沒有新增 schema。STOP 仍為指定分館、ADD 仍為非固定日加送。

1. 先送 preview=true，僅計算、不寫入。畫面逐項顯示來源日期／數量、目標日、原有數量及結果；支援大量分館、手機捲動及鍵盤取消。
2. 每個來源順延至同分館嚴格晚於來源日的下一個可配送日；跳過本次完整停送範圍、既有全館休館、本站 STOP 及非配送星期。尊重有效 ADD，分館或路線停用、超過一年找不到配送日則拒絕。
3. 沒有目標預填時直接搬移；目標已有預填（包括 0），或多個來源匯入同日，預設回 409。必須明確勾選同意，送 conflict_policy=sum 才相加；不覆蓋原量。預覽 plan_token 過期回 409，須重新確認。
4. 僅接受 WAITING_SECRETARY / WAITING_DRIVER 的公文預填。司機填入 0 也算已操作；圖書、回送、簽收、更正、行政結案、隨車品項、支援司機指派、路線／區段簽名或鎖定日報均阻擋，不搬移這些資料。歷史日期不可變更。
5. 全範圍於同一交易完成，含來源、目標、排程及 audit。SQLite 使用 BEGIN IMMEDIATE；PostgreSQL 使用共同 transaction advisory lock 194020，與預填、司機出貨、品項、交接及簽核寫入協調。來源另檢查 row_version；失敗整批回滾。
6. 來源保留原 ID／document_original，以 VOID 及 SCHEDULE_POSTPONED:目標ID 標記，清空 final；目標保留既有 original、更新 final。來源實際搬移量與目標前後量寫 audit，可追溯已更正過的預填。相同或並行請求不再次搬移。
7. VOID 不納入數量報表／月累計，管理者全部資料仍可追溯 VOID。另修正月累計引用不存在 inbound_original 的既有錯誤，改用實際 inbound_final。
8. 取消停送不自動把公文移回。仍可配送的來源恢復為空白待填，已搬移量保留目標；操作前提醒並記錄 audit。請由總館重新確認恢復日數量。

舊呼叫端可沿用原參數；遇數量衝突仍須重新預覽及明確選擇相加，不能靜默覆寫。若某站已開始配送，整批阻擋，請縮小範圍並人工處理異常站，不能藉本功能搬移簽收紀錄。

## 歷史簽名

分館最近 12 個月歷史卡片／表格新增「查看簽名」，以唯讀視窗分別顯示原始與更正簽名、姓名、時間。

- GET /api/branch-session/history 僅增加 has_signatures，不批次傳輸圖片。
- GET /api/branch-session/history/{delivery_id}/signatures 依既有 session 限定本站、有效分館、最近 12 個月及非 VOID。未登入 401、跨館／超出日期／VOID 404、停用分館 403。
- 圖片只接受 PNG/JPEG Base64 data URL；其他格式明確提示，不執行。姓名／時間用 textContent，不插入 HTML；關閉後恢復焦點。
- 不變更既有簽名儲存、更正及補簽流程；管理者／總館原歷史簽名查詢保留。

## 士林 K13

在既有啟動名冊同步「建立缺少分館」之前修正身份，避免先新建 K13 而遺失 K13S 的身份連結。

- 只有 K13S：原 ID 改為 K13／士林，保留 PIN hash、QR token hash、建立時間、聯絡資料及全部配送／簽名關聯。同步更新名冊文件／CSV。
- K13、K13S 同時存在：保留兩個 ID，不合併、不刪除、不改歷史簽名；停用舊 K13S，寫 SHILIN_IDENTITY_CONFLICT audit（含 canonical_branch_id）。舊站待配送及身份合併必須由管理者人工核對，不能自動套用 K13 的 QR/PIN。
- 重複啟動冪等，異動才寫身份修正 audit；未把 QR/PIN 或簽名內容寫入新增 audit。

本次沒有新增資料表／欄位，無需額外 schema migration。沿用現有啟動流程；沒有執行任何外部 SQL。正式環境將來重啟前，先備份並以唯讀方式檢查 K13/K13S 各自 ID、配送數及有效狀態，人工確認重複身份處理方式。既有 B1 additive migration 仍見 migrations/v194_branch_signers.sql。
