工具版本、安裝程式／Hook 檢查與實際執行結果見 [TOOLCHAIN.md](./TOOLCHAIN.md)。原始JSON、log及圖片均僅留在本機 evidence/、已排除Git追蹤，下方圖片連結只供本機閱讀，不能視為GitHub附件。人工建議與自動量測分開標示。沒有因為兩個掃描器 0 finding 就宣稱 WCAG AA 通過。

## Taste-Skill 視覺方向

採 **App Screen：既有運送工作台的精修**，與 Impeccable **Operate** 一致，不套用行銷頁設計。這是建議方向，不是已執行 draw 或已落地的新設計。

- 保留現有角色入口、分館／路線切換及配送操作順序；不增加新 sidebar、重新分組角色或搬移危險操作。
- 沿用深色文字、淺底、既有系統中文字型與狀態語彙；減少同級區塊的視覺競爭，不以換字型或加插圖當作改善。
- 手機以 16px 主要文字、20～24px 頁題、清楚的數字層級及 16px 主要間距作試點目標；數字右對齊、tabular figures，四項數量均保留。
- 狀態以文字為主、顏色為輔。已完成運送、待分館簽收、待補簽仍由既有 status 對應，不能把「運送完成」改成「簽收完成」。
- 主要觸控控制目標至少 44×44 CSS px；不製造多個同權重的滿版主按鈕。不能為了簡潔而把任何原有操作拿掉。
- 表格在手機使用既有卡片視圖或容器內捲動，資料不消失、整頁不橫向溢出。此提案不改任何加總／Excel／PDF／Email。

## 四角色改善建議與五種 playbook

本輪採人工檢查／提案模式：critique、audit 不修 code；adapt、harden、polish 只產出確認後清單，**沒有執行其修改步驟**。這五種名稱是 agent playbook，不是五個可宣稱自動通過的 CLI 測試。

| 角色 | critique：主要任務 | audit：重點核對 | adapt：響應式提案 | harden：待驗收邊界 | polish：最小精修 |
| --- | --- | --- | --- | --- | --- |
| 司機 | 看目前路線，填數量，核對並完成本站 | 四數量均可見、input label、按鈕命中區 | 保留既有路線切換；手機單欄與四數量成組，桌機保持原作業排列 | 0／未填分開；長分館名、待補簽、更正後重確認、斷線不重送 | 調字級、間距、數字對齊、狀態與按鈕主次 |
| 分館 | 核對配送日／四數量，填姓名並手寫簽名 | 日期、姓名與簽名標籤、焦點、歷史補簽入口 | 保留今日及歷史任務選擇；簽名區不被鍵盤／底部按鈕遮住 | 無任務、名單載入失敗、清除簽名、數量留白沿用、歷史不可覆寫 | 標籤及錯誤位置一致；下拉依功能規格確認後再處理 |
| 總館秘書 | 看各路線進度、填公文、完成路線／日終簽核 | 已運送與已簽收區分；日月報欄位、路線簽名條件可讀 | 保留既有日報／月報卡片與桌面表，手機在表格容器內捲動 | 部分待補簽、簽核已鎖、日期跨月、空報表與失敗載入 | 數字靠右、表頭／單位一致、簽核動作附近列出現有未完成條件 |
| 管理者 | 分館管理、查看異常、設定現有休館／停送 | 有效與停用館別可辨；目前可用權限及操作後果 | 保留既有分館搜尋及頁籤；手機篩選換行、小按鈕可觸控 | 長館名、無結果、衝突訊息、尚未實作順延不可假成功 | 明確危險操作層級，與編輯／查詢視覺分開 |

登入後畫面及完整 interaction path 未實測，不給看似精準的整體UX分數，也不宣稱 WCAG AA、效能、簽名或手機手勢已通過。

## 原司機試點提案（已確認，執行結果另列）

建議第一批只改 `app/static/driver.html` 的語意標籤／class 及新增專用 CSS；不改任何 inline JS 函式、API路徑／method／payload、shared common.js、後端、資料庫、報表、簽名儲存或配送邏輯。先以現有 UI 的字級、層次、焦點、間距及觸控尺寸做小幅精修，保留所有原有入口。

確認後再開實作分支／Draft PR；差異應限定於上述UI檔案。驗收需包含320、390、768、1440寬度、200%縮放、鍵盤焦點，以及使用授權的隔離測試帳號操作路線切換、數量存檔、待補簽、更正與路線手寫簽名。同一筆資料與狀態比較前後，重跑16項回歸並補UI行為測試。先產出報告不等於已獲准執行這些修改。
